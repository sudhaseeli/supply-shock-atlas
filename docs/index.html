What the data shows

    Four crises, side by side

    Each crisis is compared with the same weeks one year earlier, which removes seasonality. The tables rank ports by the number of weekly calls lost or gained, in the affected zone and where traffic could have gone.

    By country, inside the affected zone

    Traffic that shifts at the same time isn't proof that one caused the other. Gains can also reflect growth that was already under way. Zones are drawn as map boxes around each crisis.

    Does the detector actually work?

    The detector never sees the IMF's disruption log. Afterwards, each logged event is checked for an alarm at the affected ports. As a placebo, the same ports are checked over the same dates one year earlier, which shows how often an alarm would fire by chance.

    Which countries lean on one port?

    The busiest countries where one port handles at least 60% of maritime imports, according to the IMF port database. Calls a week covers the last 52 weeks.

    Do ship movements track supply chain pressure?

    The New York Fed's Global Supply Chain Pressure Index is built from freight costs and manufacturing surveys, not ship tracking, so it's an independent check on the stress index.

    How it's built

    BronzeResumable, verified downloads from a flaky API. Each port's row count is checked against the server.
    SilverRevisions resolved, zero days rebuilt, a complete weekly panel, network-wide feed outages flagged.
    GoldRobust scoring against each port's history and season, alarm episodes, backtest and crisis marts in DuckDB SQL.
    Quality gateCritical failures stop the run, so nothing wrong gets published.
    AtlasStatic JSON and this page, hosted on GitHub Pages.
